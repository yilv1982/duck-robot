# 问题是否存在：舵机堵转过流会烧 HAT 吗？

日期：2026-10-10。用户要求先分析故障是否真实存在，而不是继续推进配电改造。本轮只做证据审查与文档纠偏，未改硬件/软件参数，未采购或做堵转/短路实验。

## 一句话结论

**堵转造成 HAT 直通供电路径过热/损坏的机理存在，但目前没有证据证明本机 HAT 会因一次短时堵转烧坏，也没有足够信息证明现有保护一定来得及。** 更明确的发现是：C001 厂商规格将过流卸载标为出厂默认关闭，不能预设“卡住后马上保护”。下一步应核清实际保护配置与供电路径，而不是先认定必须增加配电板。

## 1. 纠正问题表述

- 应分析的是“堵转电流在保护动作前，是否超过 HAT 通路在对应时间内的耐受”，不是“过流保护本身会不会烧板”。关闭舵机输出通常减少电池负载；关断时可能出现的电感/回灌电压尖峰属于另一个需要波形证据的风险，不能混同为已经发生。
- **堵转不等于瞬时**：电机被卡住，只要控制器持续施力且未及时限制/卸载，就可能形成持续负载；短促受阻、长期顶死、多关节同时受阻和反复重试是不同工况。
- 堵转电机有绕组阻抗及驱动/PWM控制，不等于电池正负直接短路。线束短路必须另做保护设计，不能用舵机内部保护兜底。

## 2. 按 V1.0 图纸，电流经过 HAT 的哪里

证据：[Power 页](../microduck-hat-20261006/page2.png)、[Servo 页](../microduck-hat-20261006/page4.png)。实物 V1.2 是否有新增串联件仍待核，以下仅按已有设计及本会话的 A 进/B 出候选路径分析。

```
电池 → 输入座/触点 → HAT +BATT 铜箔 → 输出座 → 舵机电机驱动
                    │
                    └→ 板内降压 → 5V → 主控
回流：舵机 GND → HAT 地铜/接头 → 电池负极
```

- 舵机的主动力电流通过接头、焊点、+BATT/GND 直通网络，**不流经给主控供电的 AP63205 5V 输出支路**。
- AP63205 的 2A 是其降压输出规格，不能拿它作为 HAT 舵机母线总额定，也不能据此说舵机超过 2A 就烧降压器。
- 如果 V1.2 电路相符，热风险直接落在输入/输出连接器、压接、焊点及 PCB 通路；主控和其他芯片还可能受电压塌陷、地弹或过压瞬态影响，不能凭静态图给出损坏先后次序。
- 存档图的 F1/D3 是数据路径元件，不是舵机电源保险。没有核到 V1.2 动力保护电路或动作曲线，不能认定板子会自己断开。

## 3. 为什么“3A 座 + 3–5A 参考电流”不能直接推出瞬时烧板

- EH 的参考额定与特定端子/线规/温度条件相关，不是“3.01A 瞬间烧毁线”；实物具体系列/材质还未验证。
- 社区“正常 3–5A”不是本机电流波形，也未给当前各段实际分配、占空比和持续时间；15×堵转电流只是极端同时受力的算术情形，不是每次卡一颗都出现的电流。
- 热损耗近似 `P = I²R`，短时间忽略散热、R 近似不变时能量 `E ≈ I²Rt`；同电流 10ms 与 1s 的热输入相差 100 倍。实际损坏还受接触状态、铜厚/宽度、热容量、重复频率和初温影响。
- 因此较低额定与较高参考负载说明**需要验证裕量**，不说明已经烧板，也不批准任意超额脉冲。若实测连续电流确实超过实际额定，即使暂时没烧也不应当作合格。

## 4. 关键新证据：舵机过流卸载默认并非开启

### 厂商规格（直接一手文件）

[HD-1910-C001 规格书](../../../references/microduck-replica/tools/FeeTech_HD1910M_Servo/HD-1910-C001串型规格书20260907.pdf)，A/0，2026-09-07：

- **PDF 第 3 页 / 印刷 2/7，5-6**：7.4V 堵转电流 2A±10%（6V 为 1.6A）；未给当前本机 8.4V 实际电流曲线。
- **PDF 第 5 页 / 印刷 4/7，7-11**：过流描述为运行电流大于 0.5A 并持续 2s 后关闭输出，重新发位置指令清除过流保护标志，电流和时间可以自定义；明确标红“**出厂默认关闭**”。
- 同页过热保护为大于 80°C 关闭扭矩输出，出厂默认开启；这是舵机内部测温，不是测 HAT 接头/铜箔，不能当作 HAT 温度保护。

**0.5A/2s 是规格书中的功能描述，不是本轮推荐设置，更不是用户实物已读取的参数。** 保护可能因批次、固件、运行模式、已有配置、工具初始化而不同。模式 0 的目标电流限力控制与模式 4 的 PD 控制不同，不能把一种模式的电流行为套到另一种。

规格书只写“新位置指令清除保护标志”；不能仅凭这句就量化 robotd 连续位置指令下的恢复电流/占空比。至少不能假定触发后会永久锁断，需核验实际固件与命令行为。

### 社区实测与工具代码（不是本机结果）

- [调试器 README](../../../references/microduck-community-kit/software/hls_servo_debugger/README.md)“另外两条实测结论”：2026-10-03 在 16 台 HD-1910-C001、固件 3.46 上回读寄存器 `19 = 4 (0x04)`，只有 BIT2 过热，BIT3 过流未开。
- 同 README 初始化段落说明界面电压/过流保护默认不勾选；[provision.py](../../../references/microduck-community-kit/software/hls_servo_debugger/hls_debugger/provision.py)的 `PROTECT_OVER_CURRENT_DEFAULT = False`，初始化按读改写更新卸载条件位。它可能将原来已打开的 BIT3 清除，不是“没勾就不碰它”。
- 该默认来自作者对失力跌倒的取舍，不代表合理保护对本机不必要；本轮不认可“为防摔倒关闭电气保护”作为默认工程结论，也不擅自改配置。

## 5. 逐种情况的判断

| 情况 | 已能判断的内容 | 尚不能下的结论 |
|---|---|---|
| 一颗舵机短促受阻后自行恢复 | 会增大该关节及上游相应路径负载；是否损伤取决于幅值/时间/重复率与路径 | 不能由 2A 单颗堵转值或 3A 接头额定直接说会瞬间烧 HAT |
| 一颗长期顶死，保护未开或不断恢复 | 可能持续发热，供电接头/铜箔和舵机本体风险增加 | 不知道用户配置，不能给“安全维持几秒” |
| 多颗同步受阻、其他关节同时工作 | 总电流相加，更可能出现较大压降或发热，保护按单颗动作未必限制总线 | 不能把 15×2A 直接当实际必然峰值，电池内阻/驱动/限流等会改变它 |
| 过流保护已启用并动作 | 受保护舵机输出关闭，有助于降低其负载 | 不证明在损伤之前动作，不证明会断整机电源，也不证明不会被新指令恢复 |
| 线束/板上短路 | 故障电流可能绕过舵机控制器 | 不能靠舵机过流/过热保护覆盖 |

**即使每颗都没有超过自己的过流阈值，许多颗相加也可能超过公共路径能力。** 所以“打开每颗过流保护”不是“给 HAT 总入口设置了电流上限”。

## 6. 先查哪些信息，再决定要不要改配电

1. 用户舵机实际型号/固件和只读寄存器回读：19（是否开 BIT3）、28（保护电流）、38（延时）、33（模式）；同时检查 RAM 目标电流/限幅与运行软件是否改写这些值。寄存器地址来自[协议说明](../../../references/microduck-community-kit/docs/飞特通讯协议说明.md)，解析须按对应型号/模式核准。先读，不擅自开启/禁用/改阈值。
2. HAT V1.2 的实际 +BATT/GND 路径，是否存在串联开关/保护，实际连接器/线材和 PCB 通路规格；不要拿 5V/2A 代替动力总线能力。
3. 在已确认的安全测试条件下取得输入及舵机支路电流/电压波形、动作持续时间、接头/通路温升，并按保护响应比较耐受；台架平均电流或手摸不等于完整证据。
4. 不为“先判断风险”故意堵死整机、短接电池或取消保护。若参数/图纸已经证明额定不满足，先改设计，不再以过额实验试探能否侥幸运行。

本轮结论是**暂不把增加 hub/换接头定为既定任务；先核实实际保护配置和电流路径**。有风险机理、存在保护可能未开启的一手证据，不等于本机故障已经复现或断言当前 HAT 必然烧坏。
