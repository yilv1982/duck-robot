## 三、计划不合理之处

1. **电池保护必须闭环，但外置保险不应默认采购（2026-10-12 后续复核）**。本报告原建议“保险与总开关应在 banana_pcb 装配完成前到位”现予收窄：独立保险并非一概必需，先登记电池准确型号并核实 BMS/输出短路保护是否足以保护外部线束；现阶段不采购保险丝/保险座。资料确认内置保护足够时可省去外置保险；没有或无法确认时，才设计外置保险，并在使用电池前完成保护路径核准。台架测试仍按操作单使用限流电源。
2. **EH 入口载流这个核心矛盾的裁决条件不齐。** 整个 v2 单链路线最大的未知数是 A 口约 3A 额定 vs 整机常态参考 3–5A。裁决需要：① HAT V1.2 图纸（索取无进展、无跟进记录）；② 整机真实电流波形（D 段才测）；③ EH 压接端子（整机改线必需，未购）。测试链走到"低负载动作"就会触及未知额定，届时才发现缺件会停摆。**EH 压接端子/胶壳采购应提前**（15 根线改 EH 本来就是整机前必做项）；V1.2 图纸索取应记录发出时间与退路（拿不到就按实测自建 V1.2 网络图）。
3. **舵机清点与改 ID 没有排进测试序列。** 15 颗舵机预期出厂全 ID 1，整链通信（清单第 4 步）之前必须逐颗改 ID，而改 ID 要用台架（微雪板 + 过渡期杜邦线）。这实际应插在 B5「单舵机 ping」之前成为独立阶段，目前 PROGRESS 待办里有清点项但与测试单未挂钩。杜邦过渡方案（公头插 AMP2.0 母壳、脚序交叉、胶带固定）可靠性差，**需要写明操作纪律：单次只接一颗、蜂鸣档逐根核对、不带载**，并准备失败退路（直接换 EH 压接头再上）。
4. **软件部署完全空白。** B4「插 Radxa ssh」的前提"已烧卡可 ssh"无落实计划；robotd + 飞特补丁编译/部署、ttyS2 串口配置、HLS 调试器使用均无文档无待办；C 线已知缺口（`microduck_feetech` 完整源码上游未推送、需以补丁+基线 f0d934e 重建）也没有对应的软件任务。硬件验证一旦通过，软件将立即成为瓶颈。**建议现在就开 Radxa 烧卡与 robotd 构建的文档骨架**，与硬件测试并行。
5. **IMU 刷机链路已具备并行条件但未安排。** DAPLink、烙铁、固件包全部到位，IMU 独立台架验证（操作单 C3）不依赖 HAT，可以随时先行；目前 PROGRESS 没有提示这条线可以并行压缩关键路径。
6. **banana_pcb 装配依赖未确认的打印能力。** 手顺含"打印 banana_pcb_locker"，但打印件清点（版本/材料/缺件）未完成，本机是否有可用打印渠道未记录；若需外发打印，周期应计入。
7. **电池登记是多项决策的前置，到货后未办。** 化学体系/串数/触点/BMS 能力同时是保险选型（过流保护方案 §5）、低电量阈值校准、banana_pcb 配合设计的前提，到货已登记但参数未核。

## 四、建议的调整顺序（近期三件事）

1. 登记电池准确型号并核实内置短路/过流保护；仅在保护不足或无法确认时，才进入外置保险选型。直流总开关/断电连接件另按电流与通断工况选定。
2. Radxa Zero 3W 烧卡 + robotd 飞特补丁构建环境搭建，文档骨架落盘。
3. 舵机清点 + 微雪板台架逐颗改 ID（脚序交叉核对纪律写入操作单），为 B5 铺路。
