## 延伸问题（2026-10-20）：为什么必须「先转到 2048 装舵盘」再做中位校准

用户提问：装配流程第 1 步（FD 转到 2048 再装舵盘）是不是因为飞特舵机的舵盘在单方向有旋转上限？用户观察机械结构上并没有这种限位。

### 结论（否定用户猜测）

**不是舵盘的机械上限。** 25T 舵盘花键齿均匀、无方向性，输出轴也没有"单方向挡块"；上游对位标准本来就是孔位对齐（见上文第 3 条）。真正的约束全部在电气/固件层，由三个事实决定（均为**上游台面实测**，HD-1910-C001 固件 3.46，记录于 hls_servo_debugger README；本机未复测）：

1. **位置读数是单圈编码器坐标 0~4095（= 360°），2048 是一圈中点**。整机按单圈模式跑（9/11 号 = 0/4095）时固件把位置坐标夹在 [0, 4095]，出窗回绕（负值回绕成 4096+值），实测负目标被夹、舵机不动。
2. **「中位校准」（CAL `0x0B`）的实现是改写 31 号位置偏移 OFS**，不是魔法重置：实测 CAL 前位置=72/偏移=0 → CAL 后位置=2048/偏移=−1976。
3. **大偏移不可靠**：写大偏移会让固件坐标重锚、读数折进约 ±2 圈窗口回绕，手册未定义（协议说明 12.5 未确认项）；上游经验规律是"所需偏移越小越可靠，校准前让读数落在目标附近最省事（舵盘换个齿位即可）"。

### 两步各自的分工

- **先转 2048 装舵盘 = 粗对零**：舵盘只能按 14.4°/齿 离散对齐，"就近装"后关节直位对应的原始编码器读数离 2048 最多半齿（7.2° ≈ 82 计数）。
- **中位校准 = 精对零**：把这半齿以内的残余误差 + 手扶摆直的误差用一个很小的 OFS 偏移电消掉（≤ 约一两百计数），落在实测可靠区。

### OFS 到底是"什么相对什么"的偏移（2026-10-20 追问）

OFS 是**「位置读数坐标系」相对「编码器原始计数」的原点平移量**：`位置读数 = 编码器原始计数 − OFS`（上游对大偏移四点的复算给出 `位置 + 偏移 = 编码器` 常数关系；协议文档"OFS = 0 时读数就是编码器值"是特例）。CAL 的写入公式可由实测数字反推且完全自洽：`新偏移 = 当前编码器值 − 2048`（CAL 前 72/0 → CAL 后 −1976/2048：72 − 2048 = −1976，72 − (−1976) = 2048）。

三个澄清：OFS 不是舵盘相对轴的机械角度（齿位是物理量，电写不进）；不是相对"关节直位"（舵机不知道结构件在哪，"直位 = 2048"是校准之后才成立）；改 OFS 不碰机械，只平移整个读数坐标系——56/42/9/11 号等所有位置值同时在新坐标系解释，这正是大偏移撞回绕/重锚坑的机制（窗口被平移出物理量程后固件折叠行为手册未定义）。

### 「转到中位」发的指令序列（2026-10-20 追问，源码查证）

**没有专门指令**——就是一次普通的位置伺服运动，全部由 WRITE(0x03) 写 RAM 寄存器完成。工具 mid 工艺的实现（`provision.py:881 _calibrate_mid`，默认 speed=60/acc=30）：

1. 33 号工作模式写 0（位置伺服）；
2. 40 号扭矩开关写 1；
3. 41 号加速度写 30（1 计数 = 8.7 °/s²）；
4. 46 号运行速度写 60；
5. 42 号目标位置写 2048（BIT15 符号幅值编码，2 字节小端）；
6. 主控轮询 56 号当前位置，误差 ≤ 8 计数（≈0.7°）判到位；
7. **不关扭矩**——位置环持续锁住输出轴停在 2048，装配时"扭矩锁定"即来源于此。

页面「位置控制」按钮走同一机制：`POST /api/move` → `write_pos_ex()` 用**一条 WRITE 从 41 号连写 7 字节**（acc + 位置 + 转矩 + 速度，等价飞特 SDK WritePosEx）；FD 上位机转 2048 同理。与 CAL 的本质区别：CAL 是特殊厂商指令 0x0B 改坐标系（OFS/EPROM，掉电留存）；转到中位只驱动轴、不写任何 EPROM，掉电后除轴停在物理位置外无痕迹。

若省略第一步、任意角度装舵盘：关节直位的原始读数可能离 2048 半圈远，CAL 需要写 ±2048 量级的大偏移——正踩上游实测的重锚/回绕坑；且零点偏太多时，单圈坐标下一侧行程会顶到 0/4095 编码器量程边。附带好处：零点 = 一圈正中，两侧行程余量对称，后续软件限位与训练关节角才对称。
