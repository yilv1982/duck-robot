# 机械装配与中位校准调研（2026-10-17；2026-10-20 复核）

## 现行结论与范围（2026-10-20）

用户问：“先在 FD 转到 2048，再装舵盘，最后扶直 CAL”是否必要；如果不先归中、校准偏移很大，是否危险。本轮核对厂商资料、上游记录和本地工具源码，只更新文档，没有操作舵机、修改工具或进行新测试。当前路线仍为 C 线 HD-1910-C001。

**未装舵盘时，先归中、选最近齿位装盘、再按正确机械零姿态 CAL，是推荐的低成本装配工艺；“先到 2048”不是 CAL 的协议前提，也没有证据支持“不先归中或大 offset 必然烧舵机”。** 已装好的关节不因偏移绝对值大就一律拆装，也不要为补做第一步而盲目驱动到旧坐标的 2048。

| 操作 | 实际作用 | 与装配的关系 |
|---|---|---|
| FD/工具“转到中位 2048” | 写运动目标，让输出轴实际旋转到当前坐标的 2048 | 适合轴未受机构约束时建立装盘参考；不是坐标校准 |
| 扶到机械零姿态后 CAL（`0x0B`，无参数） | 把当前位置重新定义为中位，并改变位置偏移 | 对 C001 的已核上游记录，中位是 2048；不是让轴跑到旧 2048 |
| 恢复扭矩 | 控制器重新执行有效目标 | 校准/手动摆动后须处理旧目标，不能只凭 CAL 应答直接使能 |

先归中能减少装盘后所需的**剩余校准修正**。这以原 offset 已知（通常出厂为 0）、选齿位和结构朝向正确为前提；已有未知偏移时，仅到 2048 不保证最终 offset 的绝对值小。本轮不建议为了追求“小数字”自动清零 offset。

## 为什么推荐先归中，但不能把大偏移当作烧机原因

### 装配工艺与机械零姿态

S4 第 271–274 行明确写的是“FD 先转 2048 → 装舵盘，齿位对不准就近 → 扶直 → 中位校准 → 锁紧螺丝”。它包含选近齿位后再校准，不能简化成“孔位能装上就已经完成零位”。

S4 第 264 行的机械零姿态是**腿直、脚平放、脖子竖直、头平视**；第 266 行说明站姿/home 含髋、踝、头颈非零偏角，不能直接校为 2048。踝关节的“脚板跟小腿成直角”也有其 README 第 164 行说明，旧“没有文档依据”的绝对说法不成立。嘴等关节须按自身基准确认，不能套用“腿直”。本机各关节基准仍待逐一确认。

**几何推算**：25T 对应 `360° / 25 = 14.4°/齿`。装配结构允许选最近齿位时，理想残差不超过半齿，即 `7.2° × 4096 / 360° ≈ 82 ticks`。这是几何估计，不是实测、CAL 容差或厂商安全阈值；不能忽略结构朝向、孔位约束和已有 offset。无需把 25 档试遍才判断版本或装法问题。

S3 没有要求先归中；S4 允许半圈装配误差由校准纠回。S5 的 `72 → 2048，offset 0 → −1976` 是约 `1976 × 360 / 4096 ≈ 174°` 修正成功的上游反例，足以否定“大修正必然失败”；它不能保证任意批次、固件、反馈相位和工具流程都安全。

### OFS 是什么，以及公式能说明到哪里

OFS 是位置坐标偏移，不是舵盘相对输出轴的机械安装角，也不是舵机自行识别的“关节直位”。在**一致的反馈窗口与坐标约定**下，可以用 `p = e − OFS` 解释位置读数；这里 `e` 是按同一展开/取模约定表示的编码器坐标，不能把不同圈数/窗口的数值直接混算。

S5 单次 CAL 例子中，原 offset 为 0、位置为 72；令该窗口内 `e=72`，则 `OFS=72−2048=−1976`，与校后位置 2048 相符。这支持该例子的坐标平移解释，**不构成固件跨圈行为的统一公式**，也不能证明写 OFS 会自动同步重算或重解释地址 42 的目标和 9/11 的限制，仍须处理恢复扭矩前的目标对齐。

因此，不采纳“≤一两百计数是已实测可靠区”“零偏大则一侧必顶到原始编码器量程边”的推断；25T 的半齿估计只是几何残差，不是偏移安全阈值。舵机轴的 `No limit` 也不能消除整机结构、线束和运动目标的约束。相关旧论证已原样放入[并发版本归档](archive/research-origin-31d5794.md)，以下证据和反证继续有效。

### 偏移、反馈窗口与实际负载是不同问题

- 地址 31 是位置坐标偏移，不是电流/扭矩设定。偏移大不能直接推出电流大；坐标/目标不一致造成错误运动、机构受阻后，才可能形成持续大负载。S1 注明过流/过压保护默认关闭，不能假定会自动卸载；本机保护位仍按既有安排在带载动作前回读。
- HLS 地址 31 用 **BIT15 符号 + 幅值**，范围 `−4095…4095`，不是二补码。不能因 [replica 飞特资料 README](../../../references/microduck-replica/docs/飞特资料/README.md)第 8 行把 HD-1910 归入 STS，就套用 STS bit11 偏移编码；C001 专用差异仍须结合 S1 与实际固件。
- 9/11 的单圈目标限制与 18 号相位 BIT4 的反馈表示是两件事。**单圈目标限制不等于当前位置反馈永远在 `0…4095` 内。** S5 上游记录 `18=0x34`，手推过整圈后 `head_yaw` 读到 6289，驱动取模后写目标引发整圈回转，并挤压相邻关节触发过流。这是上游叙述，本地无原始日志，不写成本机事故或必现规律。
- 早期“大偏移重锚”实验含 `−4591`，已超出 S2 的 `±4095` 范围，不能证明规范范围内的大偏移必然异常。社区 README 第 363–374 行后来收窄为“显示窗口取模”，且明说公式尚未真机验证；第 370 行“每行位置 + 偏移严格等于 −7687”也不准确，所列值只能支持**模 4096 同余**。本项目不采用旧因果定论，也不据此自动写公式修正。
- 当前 `provision.py` 已按单圈目标和 2048 零点组织流程，并有超窗检查/处理。旧[飞特通讯协议说明](../../../references/microduck-community-kit/docs/飞特通讯协议说明.md)§13.4 末尾推荐多圈的文字不能当作现行整机依据；本轮不切多圈、不改相位，不把上电重启当通用补救。

### 当前工具不能替用户消除旧目标跳动

以下适用范围为本地参考版本；板上部署状态本轮未重新读取。

| 流程 | 已核行为 | 使用含义 |
|---|---|---|
| C 线 CAL 按钮 | `protocol.py:629–646` 关扭矩 → 解锁 → CAL → 上锁；不写目标 42、不重新使能 | 有应答不能替代校后读数确认，也不代表目标已对齐 |
| C 线初始化 CAL 分支 | `provision.py:783–799` 读前后位置/偏移，但未把 `after ≈ 2048` 作为成功判据 | 成功提示主要说明指令流程收到应答，仍应核对结果 |
| C 线扭矩按钮 | `server.py:523–530` 直接写地址 40 使能，没有先对齐目标 | 手动摆动/CAL 后，不能以为点开扭矩会自动保持当前位置 |
| C 线 mid | `provision.py:881–898` 先写模式 0、使能，再写加速度/速度/2048 目标 | 会实际转动，且使能先于新目标；已装机构不能盲点 |
| B 线 `torque_on_aligned` | `server.py:996–1025` 读当前 → 写目标 42 → 回读一致 → 使能 | 只证明 B 工具有此处理，不代表 C 工具已有；本轮不改功能 |

CAL 后坐标已变，旧目标的数值可能还留着；手动摆动也会改变当前位置与目标的差。“校准时没转”与“接着开扭矩不会跳”是不同结论。正确零姿态、当前反馈、目标与机械行程须一致，不能用 offset 大小替代这些条件。

## 2026-10-20 本机追问与实测补充

以下五节为本机当日追问（工具源码/协议查证）与板上 :8765 实测记录，与上文复核结论并存：**"大偏移危险"机理的现行适用范围以节内"适用范围限定"段为准**（仅针对手动写 31 号寄存器凑目标的路径；CAL 路径 OFS 有界、到不了危险区），"齿位就近把 OFS 压到百计数级"属几何推理而非实测安全阈值，与上文"不采纳'已实测可靠区'推断"一致。

### 「转到中位」发的指令序列（2026-10-20 追问，源码查证）

**没有专门指令**——就是一次普通的位置伺服运动，全部由 WRITE(0x03) 写 RAM 寄存器完成。工具 mid 工艺的实现（`provision.py:881 _calibrate_mid`，默认 speed=60/acc=30）：

1. 33 号工作模式写 0（位置伺服）；
2. 40 号扭矩开关写 1；
3. 41 号加速度写 30（1 计数 = 8.7 °/s²）；
4. 46 号运行速度写 60；
5. 42 号目标位置写 2048（BIT15 符号幅值编码，2 字节小端）；
6. 主控轮询 56 号当前位置，误差 ≤ 8 计数（≈0.7°）判到位；
7. **不关扭矩**——位置环持续锁住输出轴停在 2048，装配时"扭矩锁定"即来源于此。

页面「位置控制」按钮走同一机制：`POST /api/move` → `write_pos_ex()` 用**一条 WRITE 从 41 号连写 7 字节**（acc + 位置 + 转矩 + 速度，等价飞特 SDK WritePosEx）；FD 上位机转 2048 同理。与 CAL 的本质区别：CAL 是特殊厂商指令 0x0B 改坐标系（OFS/EPROM，掉电留存）；转到中位只驱动轴、不写任何 EPROM，掉电后除轴停在物理位置外无痕迹。

### 编码器计数不可写（2026-10-20 追问）

协议 12 条指令（PING/READ/WRITE/REG_WRITE/REG_ACTION/RECOVERY/REBOOT/参数备份/SYNC_READ/SYNC_WRITE/RESET/CAL）中**无任何"写编码器"指令**，唯一碰零点的 CAL 写的也是 OFS(31)。内存表中编码器计数值**没有可寻址字段**：56 号"当前位置"属 SRAM 反馈区段、权限 `r` 只读，且是"编码器 − OFS"的派生值；"磁编码器"仅在 18 号 BIT0（类型 0=AS5600/1=MT6701）、19 号 BIT1（故障保护开关）、65 号 BIT1（异常状态位）出现，均非计数值。这正是 OFS 机制存在的理由：硬件测量固件只消费不修改，搬零点只能搬刻度（rewind_position 修复读数出窗也是往 OFS 加减整圈 4096，同一原理）。

### 为什么大偏移危险（2026-10-20 追问；机理综合，证据为上游实测；**当日实测后补充适用范围限定，见节末**）

四层原因，层层递进：

1. **量程几何**：编码器物理量程固定 0~4095；OFS 平移读数窗口（`读数 = 编码器 − OFS (mod 4096)`，单圈折进 [0,4095]）。零点在 2048 + 小 OFS 时关节工作区全在窗口中部（两侧各千计数余量）；大偏移（±2000 级）= 靠硬搬坐标系凑零点，关节工作区必然被窗口边界切开。
2. **边界处读数断裂**：跨边界触发 mod 4096 回绕——上游实测单圈模式 −98→3999、−498→3599、−1998→2099。轴单向连续转，读数在边界跳 4096、看似反向；速度估计/角度差/最短路径全拿错误输入。
3. **显示问题变动作问题**：42/56/9/11 号与位置环全部活在读数坐标系。同族真机案例（上游 2026-10-05）：head_yaw 被手拧过一圈读数 6289，之后任一次写目标 2048，位置环按 4 千计数差值让脖子飞快倒转两整圈——整机场景即绕线/撞限位/甩负载；反向失效：出厂 9/11 夹限下负目标被夹到 0、舵机纹丝不动。
4. **行为未定义**：窗口折叠规则手册未写（协议 12.5 未确认项），"位置 = 编码器 − 偏移 + 取模回绕"系上游四组实测点事后复算；依赖逆向出来的行为，固件升级/批次差异都可能改变。

结论："偏移越小越可靠"是几何必然——小偏移 ⇒ 零点居中 ⇒ 全行程不跨边界 ⇒ 回绕逻辑无触发机会。"先转 2048 装舵盘 + 齿位就近"即把 OFS 压到百计数级、永远留在手册定义的单圈正常区。

**适用范围限定（2026-10-20 当日 30 号 CAL 实测后修正）**：上述"大偏移危险"四层机理针对的是**手动写 31 号寄存器凑目标**的路径；CAL 路径实测证明**到不了危险区**——CAL 以单圈编码器值为基准，产物 OFS 有界 ∈ [−2048, +2047]，且校准后零位必居窗口正中、两侧各 2048 计数余量。叠加单圈模式 9/11 夹限与关节行程远小于余量，**正规流程（CAL 校准 + 程序写行程内目标）下不存在"输入角度导致转一圈多"**。真实发生过的"转一圈多"（head_yaw 6289）根因是**圈计数**而非 OFS：轴被手掰过整圈、读数累积出窗后下指令，位置环按跨圈差值执行。**装配期实用规则：手转过的舵机，下指令前先读 56 号——读数在 0~4095 内随便用；出窗则先 CAL 或手转归位再动**（2026-10-20 30 号手转一圈半读数 −3399 → CAL 后 2048 即安全落地实例）。装机后机械限位使整圈手掰基本不可能，该入口随之封闭。三个入口完整判定（2026-10-20 补全）：① 程序正常驱动（目标 ±180° 内）：单圈闭环差值 ≤ 半圈，圈计数不会累积，绝不多转；② 目标写窗口外：单圈模式被夹到边界，不跨圈执行（多圈模式才会真转大角度，属主动行为）；③ 手掰出窗后下指令：与目标大小无关，按跨圈差值多转——唯一需主动防的入口。手掰后的处置按对象分（2026-10-20 定稿）：**未装机散件** → 手掰→CAL→下指令即安全（CAL 归位 2048 + 清圈计数 + OFS 有界，30 号当日全程实例）；**已装机已校准关节** → 不可随手 CAL（会把"手掰后停住的姿势"重定义成零位、覆盖摆直校准成果），正解 = 手转归位或 rewind（OFS 挪整圈，零位定义保留，即工具 rewind_position 语义）。已装机关节受机械限位保护、整圈手掰基本不可能出窗，该区分主要适用于装配期台面散件。

### 本机抽查：30 号（头颈）编码器/OFS 实测（2026-10-20，板上 :8765 API）

经 `/api/read` 读 30 号：**31 号 OFS = 0**（出厂未校准，符合"只改 ID、校准留装机后"的初始化决定）；**56 号当前位置 = 2047**（≈178.09°，轴停在中位附近，差 1 计数 ≈ 0.09°）。编码器值 = 读数 + OFS = 2047（OFS=0 时读数即编码器值，公式本机印证）。本机实测级别：直接读数。

**用户手动转约一圈半后复读**：OFS 仍 = 0（手转不动 EEPROM，公式再次印证）；当前位置 = **−3399 计数**（raw `47 8D`，BIT15 符号幅值）——读数跑出单圈窗口 0~4095，本机复现上游 head_yaw 6289 案例的"全角度反馈不自动回绕"现象（彼为正向出窗、此为负向）。圈数账：差 −5446 计数 ≈ 1.33 圈，与"一圈半"差约 0.17 圈（61°），手转不准或固件快速跟踪丢步无法区分（待确认）。**注意：此状态下写任何目标位置（如 2048）会让位置环按 5447 计数差值真转约 1.33 圈回正**；恢复路径 = 手转回原位，或工具 rewind（OFS 挪整圈折回单圈窗口）。

**出窗状态下执行 CAL（2026-10-20 本机实测，上游未测过此场景）**：CAL 后 **OFS = −1352、读数 = 2048**。反推：轴当时单圈编码器值 = −3399 mod 4096 = 696，−1352 = 696 − 2048（差 1 计数量化）——**CAL 以单圈编码器值为基准**（若用多圈值应为 −5447，超 31 号字段范围 ±4095 写不进）。三个含义：① CAL 产物 OFS 有界 ∈ [−2048, +2047]，危险的超范围大偏移只能来自手动写寄存器凑目标，CAL 自身到不了；② CAL 顺带清圈计数（读数从 −3399 回 2048，等效自带 rewind）；③ CAL 后"此刻物理位置"必钉在读数 2048 窗口正中（几何必然）。注意：此次把"手转后停住的姿态"钉成了零位，30 号未装机、该零位无机械意义，装机后须在"关节摆直"时重做 CAL；还原出厂 = 解锁 55 → 31 号写 0 → 上锁。

**CAL 后再手转数圈复读**：OFS 仍 = −1352（第四次验证：轴怎么转都不动 EEPROM）；读数 = **−6216**（≈ −540.8°）。相对 CAL 后起点 2048 变化 −8264 计数 = **−2.02 圈**，与"负向转约两圈"吻合（差 72 计数 ≈ 6°，手转正常误差；对比首次"1.5 圈差 698 计数"，支持"快转丢步、慢转跟得住"猜想，仍待系统验证）。**CAL 只清一次圈计数，之后手转照常累积**——再次出窗（−6216 在 ±2 圈显示窗口内、出单圈窗口），处置同前：动之前先 CAL 或手转归位。

### 舵机电压/过流保护（19 号 BIT0/BIT3）开还是不开（2026-10-20 问答定案）

**结论：不开**（维持出厂 19=4 只开过热，与 15 颗初始化决定一致）。依据：① 19 号语义是"触发即卸载脱力"，整机站立时触发=摔机，防烧能力有限；② **15 号最低输入电压出厂默认 40 计数 = 4.0V**（本机 2S NP-F550 跌到 4.0V 前早断电，开了形同虚设；调阈值则带载电压跌落可能误触发摔机，开前须实测整机带载 sag）；③ 过流只有时间参数可调（38 号默认约 2s），电流阈值不可调，防烧主力按既定路线走硬件保险丝/限流；④ 上游 16 台实测全为 19=4、15 台整机真机保持此配置（ID 10 曾手工 19=13 试验后恢复）。重评时点：带载动作测试（已有"保护位回读"待办）或长时间无人值守运行（届时先台架验证堵转确实触发）。来源：memory_table.py 14/15/38 号字段定义 + hls_servo_debugger README 保护位实测记录。

## 最短建议流程与本机下一步

1. **未装盘且轴未受机构约束**：确认原 offset/坐标状态，先归中到 2048，按正确结构朝向选最近齿位装盘。已有未知 offset 时不自动清零；已装好的不补做盲目驱动旧 2048。
2. **校准**：支撑机身/关节、关扭矩后，扶到该关节机械零姿态并保持，再执行 CAL。孔位可安装与机械零姿态是两个条件；home/站姿不能替代零姿态。
3. **恢复扭矩前**：确认当前读数约为 2048；本机容差未定，不编造阈值。再以校准后的当前坐标对齐目标并回读确认，避免执行旧目标。现有 C 线 CAL/扭矩按钮不会自动完成对齐，未确认时保持关扭矩。
4. **已有装配**：按正确基准 CAL 并处理目标，不因偏移绝对值大就一律拆盘。读数异常/超窗、方向不符或零姿态未知时再针对性排查；本轮不新增整机扫到机械极限、台架测试或通用重启步骤。

待确认项：本机各颗固件/原 offset 与反馈相位、各关节零姿态及校准结果、恢复扭矩前目标对齐的完成情况；本轮均未取得新实机回读。后续按[工具索引](../../bench-tools.md)与 [PROGRESS](../../../PROGRESS.md)继续，不把研究结论记成操作完成。
