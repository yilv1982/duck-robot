# HAT V1.2 功能确认操作单（Microduck Controller Hat for Radxa Zero 3W）

> **目的**：实物丝印 V1.2，存档原理图仅 V1.0（图物差异：背面 F303 类 MCU + 正面超级电容，见 [docs/photos/](./photos/README.md) HAT 小节）。没有 V1.2 图纸，本操作单**不做图物比对**，只用「断电通断核对 + 限流上电分步验证」确认本项目需要的功能是否 OK。
>
> **需要确认的 4 项必需功能**（依据 [power-architecture-v2.md](./power-architecture-v2.md)）：
>
> | # | 功能 | 判定门 |
> |---|---|---|
> | 1 | +BATT 进 → 板内降压 → 5V 经 40P 排母喂 Radxa | B2：排母 pin2/4 = 5.0V ±0.2 |
> | 2 | 舵机口 pin2 = 电池直通（能过 3-5A） | A2：pin2 ↔ +BATT 网导通，中间无串联件 |
> | 3 | Radxa UART2（ttyS2）→ 半双工驱动 → 舵机口 pin3 | B5：一颗舵机 ping 通 |
> | 4 | 舵机口针序 1=GND / 2=+BATT / 3=DATA | A1 |
>
> 附加排除项：F303 MCU 不干扰总线与电源（A4 + B6）。音频/RS485/板载 IMU/Qwiic 飞特路线不用，不测。
>
> 装备：德力西 6000 位万用表、德力西 DLX-30V10AMF 直流电源、Radxa Zero 3W（已烧卡可 ssh）、已配好 ID 的 HD-1910 ×1、杜邦线若干。
> 全程原则：**先断电核对，后限流上电**；首次上电限流 0.3A。板正反面照片与元件标注：`docs/photos/hat-v1.2-*.jpg`。

## A 断电核对（万用表蜂鸣/电阻档，板子不上电、不插 Radxa）

- [ ] A1 **舵机口针序**（两个 SERVOS 大白座都量）：
      pin1 ↔ 排母 pin6 或安装孔（GND）应**通**；pin1↔pin2、pin2↔pin3 应**不通**；两座 pin2↔pin2 应**通**（并联）。
      认准 1 脚方向再量，结果与丝印对照拍照存档
- [ ] A2 **+BATT 路径**：舵机口 pin2 ↔ AP63205 输入电容正极（正面 CK 6R8 电感旁）应**直通**；
      若不通或电阻档有阻值 → 中间串了保险/开关件，记下阻值并拍照识别。
      **同时定位电池入口**：用 pin2 逐个碰背面 8 个圆形焊盘，找出 +BATT 实际进板位置（决定电池线焊/插在哪），记入结果
- [ ] A3 **排母关键脚**：pin2/4（5V）↔ 排母附近 5V 网络应通；pin8/pin10（UART2 TX/RX）↔ 正面 74LVC 小芯片区应通（电阻档几十~几百 Ω 也算有路径，直通件是 0Ω 选路电阻）
- [ ] A4 **MCU 粗查**（F303 是旁观者还是参与者）：蜂鸣档从舵机口 pin3 出发扫 F303 四边引脚；再从排母 pin8/10 出发扫一遍。
      都不通 → MCU 不在舵机数据链上（旁观者）；有任一通 → 记下脚位，B6 重点观察
- [ ] A5 **超级电容**：断电态两端电压 ≈0；一端应接 3.3V 轨或 MCU 的 VBAT 脚（蜂鸣粗查），确认它不是动力链的一部分

## B 限流上电（台架电源，限流 0.3A 起步）

- [ ] B1 电源设 **8.4V / 限流 0.3A**，接 A2 找到的 +BATT 入口（红正黑负，接前拍照核对极性）
- [ ] B2 **5V 判定门**：开输出，HAT 空板（不插 Radxa、不接舵机）。正常：红屏几十 mA；量排母 pin2/4 = **5.0V ±0.2** → 过。
      电流顶限 = 短路，立即关输出查；无 5V = 电源链与 V1.0 不同（可能 F303 参与电源时序），停、拍照、记录
- [ ] B3 **总线空闲电平**：舵机口 pin3 对 GND ≈ 3.3V（上拉）；pin2 = 8.4V。pin3 若是 5V → 停，数据电平与 Radxa/IMU 的 3.3V 体系不符，需另查
- [ ] B4 **插 Radxa 点亮**：关输出 → 插 40P 排母 → 开输出。Radxa 灯语双闪→常亮，ssh 进系统，`ls -l /dev/ttyS2` 应在且无人占（`sudo fuser -v /dev/ttyS2`）
- [ ] B5 **一颗舵机 ping 通**（数据链判定门）：舵机插舵机口，Radxa 上 `feetech-servo-sdk` 以 1 Mbps ping 该 ID → 应答 = 功能 3 通过
- [ ] B6 **MCU 干扰排除**：不跑任何软件静置 5 分钟——舵机不自转、无异响、不失力矩；（可选）跑 bench 工具总线错误计数 = 0。
      若舵机有异常动作或总线有非预期数据 → F303 在往总线发数据，停，向板卡来源要固件说明
- [ ] B7（可选）PWR_DET 关机检测：排母对应 GPIO 脚电平随 +BATT 有无变化则该功能在

## 异常速查

| 现象 | 含义 | 动作 |
|---|---|---|
| B2 电流顶 0.3A、电压被压低 | 短路或接反 | 关输出，蜂鸣档查 +BATT 对 GND |
| B2 无 5V、电流正常小 | V1.2 电源链改了（疑 MCU 控 EN） | 量 AP63205 EN 脚电平；拍照记录，找来源 |
| B3 pin3 = 5V | 数据电平不符 | 停；查 V1.2 是否换了驱动供电轨 |
| B5 ping 不通 | 链路任一环断 | 顺序查：ttyS2 在否 → 占用否 → A3 结果 → 舵机 ID/波特率；最后用微雪板验证舵机本身好坏 |
| B6 舵机自转/数据乱 | F303 在抢总线 | 停；要固件说明或断开 MCU 总线脚（最后手段） |
