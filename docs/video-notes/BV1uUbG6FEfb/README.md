## 三、装配顺序与易踩坑

把视频的空间讲解转为下列学习清单；几何方向仍须回看对应 3D 展开画面，而不是只照文字盲装。

1. **先确认舵机中位，再锁结构**（04:20～04:39、12:17～12:33）。作者先假设出厂在中位，但建议不确定/碰动过就跳到归中步骤；本项目宜装前逐个确认、贴 ID。
2. **两条腿分别完成**（04:40～05:47）：脚壳与首个舵机、塑料支承/环件，再接上方连接结构；作者多次要求润滑。
3. **躯干/髋部总成**（05:48～07:22）：先固定被后续舵机遮挡的孔，再放舵机和夹持盖板，最后接回两条腿。06:31～06:38 是“先打四个螺丝，否则孔被挡住”的明确顺序提示。
4. **颈、头、嘴**（07:55～09:20）：颈部双舵机与小连接片；头部三个舵机里包含嘴部，按模型方向固定，并装塑料环/盖板。
5. **电池与板件空间**（09:24～09:39）：作者电池较大，对外壳开口有改动，板子摆在后侧。不要在装着电芯时切削/打孔，也不要照“塞进去”的口述压伤电池包。
6. **机械检查**：视频反复指出长螺丝锁死舵盘、短螺丝脱落；从动盘过紧增加阻力。未给完整逐孔长度/扭矩表，应逐关节低风险检查活动范围、间隙、干涉与线束余量。

这里的“归中”是舵机机械中位设置，不是 IMU 标定。16:36～16:56 讲的是 **IMU 安装朝向匹配已有步态模型**；视频没有展示完整 IMU 标定过程、保存标定参数或定量误差测试。

## 四、舵机配置、中位与编号：视频做法

依据 [11:05 起](https://www.bilibili.com/video/BV1uUbG6FEfb/?t=665)、[Wizard 画面组](frames/setup-sheet-01.jpg)以及[关键操作帧](frames/setup-sheet-02.jpg)：

1. OpenRB USB 接电脑，**每次只连一个舵机**。这直接说明该演示没有使用 U2D2；不能据此保证任意新购 OpenRB 的固件均已正确。
2. 在 Dynamixel Wizard 2.0 点击 Scan，进入识别出的 XL330 界面。
3. 设置 ID；作者在 12:01 说范围 1～15；12:07 设置 **1 Mbps**；12:10～12:15 把 **Return Delay Time 从 500 改为 0** 并保存。画面可读 **Protocol 2.0**。
4. 12:17～12:31 打开 Torque，点 **Center**，使舵机回中心再安装。[12:27 截图](frames/12-27-480.jpg)显示约 180°。这不是给每个关节任意设“零度”。修改 ID 等 EEPROM 前须按官方要求关闭 Torque（项目安全补充）。
5. 12:39～12:50 找到地址 **62 `PWM Slope`**，作者口述默认140，改成 **255** 并保存。[12:51 截图](frames/12-51-480.jpg)可见255，但失焦部分不要用于抄整个寄存器表。
6. 12:52～13:03 找到地址 **63 `Shutdown`**，取消最后一项 **Bit 0 `Input voltage error`** 后保存。[12:58 勾选前](frames/12-58-480.jpg)与[13:01 取消后](frames/13-01-480.jpg)可直接对照。
7. 13:23～14:02 逐个重复；作者口述 **右腿1～5、左腿6～10、头颈11～14、嘴15**。编号模型见[13:54](frames/13-54-480.jpg)。精确关节名与轴向请对照当前代码映射，而不是由 ASR 猜测。

> **安全分界**：上面第5、6项是作者实际演示的记录，不是本项目推荐配置。尤其不能靠取消输入电压错误触发来容忍超规格供电。保留电压保护，遇报警先查电源、负载和连线；XL330官方3.7～6.0V、推荐5.0V，寄存器界面允许范围不等于硬件供电许可。

## 五、电源与信号：视频实际分支，不照抄 README 泛图

### 视频能确认的路径

依据 14:18～16:24 的内部ASR校读（见[方法说明](evidence/transcription-review.md)）、[14:57 G/D 叠图](frames/14-57-480.jpg)及[接线组图](frames/wiring-sheet-03.jpg)：

```text
电池正极 → 电源开关 → 正极分支 ─┬→ 舵机总线 V（作者不接 OpenRB 的 V）
                              └→ 降压模块输入 → 稳定5V输出 → Pi电源正极
电池负极 / 舵机GND / 降压GND / Pi GND / OpenRB G：共地
舵机总线 Data → OpenRB D
Pi Micro USB ↔ Type-C OpenRB（USB连接）
IMU VCC / GND / SCL / SDA ↔ Pi 对应电源、地和I2C
```

- **14:18～14:40**：两腿分支按 V→V、GND→GND、Data→Data 合并、焊接；[14:32 正确示意](frames/14-32-480.jpg)和[14:37 错接对照](frames/14-37-480.jpg)提醒不能凭插头视觉左右混接。这是总线并联连接，不是把舵机供电串成分压链。
- **14:49～15:03**：G 接 OpenRB 的 G、信号接 D；作者说明15个舵机电流较大，因此不从OpenRB提供动力，而把动力正极接到电源分支。因此**不能断言视频把全部动力电流送过 OpenRB**。
- **关于“小跳线”**：14:57 画内字幕是“你看他写了一个D对吧”，对应 Data；本次核对没有取得明确拔除小跳线的语音/画面证据，**不记录为已演示操作**。实际板子供电选择、USB隔离及回流路径还须按硬件版本核对。
- **15:25～15:55**：先将电池红线接开关、置断开；开关后分两路，其中一路接刚才留出的舵机电源线，焊后包绝缘。
- **15:59～16:24**：另一路“6V降5V”再接 Pi 正极和 GND；[16:12](frames/16-12-480.jpg)、[16:22](frames/16-22-480.jpg)输入/输出标签可读。没有演示把6V直接送给Pi。
- **15:09～15:19、16:36～16:56**：IMU接VCC/GND/SCL/SDA，固定于背部、方向与示例一致且不歪斜。[15:17 接线图](frames/15-17-480.jpg)、[16:42 实装](frames/16-42-480.jpg)。当前仓库给出 SDA=GPIO2、SCL=GPIO3，这是**项目对照**；实际模块电源及电平必须按对应板核实，不能凭模糊焊点猜物理脚号。

### 本项目必须补齐的安全验证

- **6V是XL330上限，不是任意“标称6V电池”都安全**。视频没有电池铭牌或满充/动态测量；不采用2S锂离子/18650满充8.4V直供。需要验证全工况舵机电压、供电跌落与峰值电流、正确充电器/保护。
- OpenRB 官方 DYNAMIXEL PORTs **总额定3A**，USB有 **500mA保险丝**；不能由“板支持较高VIN”推导“舵机可用较高电压”，也不能从USB调单舵机推导USB可带全机。视频外接动力分支值得区分，但没有证明全部配电/回流路径和保险配置合格。
- MP1584商品标题“3A”不是热设计、效率或瞬态能力验证。先空载/假负载测5V输出和极性，再接Pi；模块输入压差、发热和压降另核。
- 断开动力后再焊接/并线，核对线序、共地、绝缘、应力释放；紧急断动力措施应可触及。运动前可靠支撑、防夹手、防跌落。

官方依据：[XL330-M288](https://emanual.robotis.com/docs/en/dxl/x/xl330-m288/)、[OpenRB-150](https://emanual.robotis.com/docs/en/parts/controller/openrb-150/)。本项目完整安全核查见[根README](../../../README.md)和[BOM](../../../BOM.md)，本笔记不替换那些核查。

## 六、刷机、联网与首跑（视频路线）

### 1. 镜像与首次联网

- 17:10～17:58：准备新SD卡，作者口述最好大于32GB；到项目 Release 下载 `.xz`；Pi Imager选 **Pi Zero 2 W → 自定义镜像 → 存储卡 → 写入**。作者称镜像内已有代码和模型，写入异常可先排查USB接口。刷写会覆盖所选卡，目标盘需核准；本次未下载镜像或试刷。
- 18:04～18:16：Pi接HDMI显示器、Micro USB键盘；18:17～18:30 使用镜像默认 `user` / `password` 登录。这里是视频公开的镜像默认账号说明，不是读取本机账号；实际使用后应修改默认密码。
- 18:33～19:02：在Pi终端执行Wi-Fi连接及自动重连，画面可核读下列形式，SSID/密码用占位符替换，不保留作者私人网络值：

```bash
sudo nmcli device wifi connect "你的SSID" password "你的WiFi密码"
sudo nmcli connection modify "你的连接名" connection.autoconnect yes
```

  “连接名”不总等于SSID，可用 `nmcli connection show` 核对（此条为实用补充，不声称视频演示过）。19:04～19:10强调 **2.4GHz，不是5GHz**。视频接着拔掉键盘/显示器、接回Pi与OpenRB；关机应按根README正常流程，不把直接断电当标准操作。

### 2. 电脑SSH与启动

19:25起，电脑和Pi处于同一Wi-Fi。Windows演示 `Win+R → cmd`；[19:51终端](frames/19-51-480.jpg)可读SSH命令，[20:12](frames/20-12-480.jpg)叠图给出完整部署启动命令：

```bash
ssh user@microduck.local
cd ~/microduck
PYTHONPATH=src .venv/bin/python src/main.py
```

这是**视频命令抄录**，不是本次已经执行。ASR把 `microduck` 误成 `MicroDark`，启动命令以画面为准。上方短暂出现的 `ssh-keygen -R microduck.local` 不应无条件执行；主机密钥变化须先确认确实是自己刷写/替换的Pi。

### 3. 首次动作与键盘

- 20:21～20:25 机器人先回正；20:29扶住；20:32按 **V** 启动步态，20:41起方向键控制。20:47以及21:00起讲上/下加减速、左右转向。[回正帧](frames/20-24-480.jpg)、[地面演示](frames/21-00.jpg)。
- **项目对照**：启动 `main.py` 就使能扭矩并回中，不能等按V才准备支撑；当前代码 `v` 切换行走，方向键累计速度、松键不清零，`x`清零、`q`退出。视频没有完整演示急停与故障处理。使用当前快照时还应显式选 `MICRODUCK_INPUT=keyboard`，避免自动选中已连接手柄；详见根README，而不是直接把视频启动行当唯一安全步骤。
